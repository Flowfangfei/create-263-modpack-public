# 十八模组联合验证

平台为 Minecraft 26.3、NeoForge 26.3.0.22-beta、Java 25。本轮在十二模组组合上新增 Electro Energetics、Storage、FluidLogistics、Additional Logistics、Dragons Plus 和 Enchantment Industry，共18个直接运行JAR、15个源码模块目录。

当前服务端创建与独立进程重启均已通过，新增六模块各轮37项检查全部通过；最终客户端进入世界、物品绘制、菜单网络与保存退出也已通过。Windows安装器实际执行并逐条目核验18个JAR通过，源码归档的导出与核验方式见仓库README。所有测试世界均由本项目新建，客户端只使用停服世界的逐文件校验副本，原HMCL存档未访问。

## 客户端进展

真实启动发现并修复Electro旧高亮事件、CDP桶颜色事件、Fluid眼镜提示/滚轮Mixin与消息处理器注册。铜桶使用原生动态ItemModel，图集扫描不再提前构造Stack；三个供水/渲染入口在实际调用时创建流体堆；粉雪源与流动流体显式注册原生FluidModel。工具及包裹世界partial使用方块图集，原物品模型、几何和纹理保留。可选联动的15个物品定义原字节移回各自集成资源目录，四个专用流体图集源按真实加载器条件启用。

最终客户端使用完整18模组进入已停服世界的校验副本，489个注册物品在GUI/GROUND/THIRD_PERSON上下文解析，十页GUI每页实际绘制超过5帧；10个世界fixture的方块实体和渲染入口核验通过。两场液压杆Ponder及实际设置菜单渲染，保存回标题与退出码0均通过。上下文解析不等同于每种地面/手持动画都已人工验收。

Storage通过实际方块交互打开背包与原生菜单点击协议：1024→私有槽960＋原版光标64→私有槽1024，客户端与服务器均保留完整组件、光标最后为空。压缩配方从自然客户端入口发送请求，由服务端构造链后回复，核验铁三阶9/9、煤二阶9/1及剑负缓存；未直接给客户端cache灌值。

截图复核并修复Storage六文件17处文字alpha，Fluid七屏13处及EE/Additional三处标题也保留原RGB补不透明通道。最终1066×600、GUI scale2截图可读背包标题、Inventory及1024/960/64数量；最终运行日志已无本轮模型加载失败、图集拒绝、重复sprite或粉雪FluidModel缺失。其他未打开界面的颜色修复有源码/原生API核对，不声称所有GUI已逐一操作。
